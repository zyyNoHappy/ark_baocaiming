## 一、这套东西干什么

明日方舟「报菜名」视频的素材流水线。

N 个人各自截几十张「干员列表」截图丢过来，本仓库：

1. 把每张截图切成一张张独立的干员卡（裁掉页面底色、边框、空白）
2. 认出每张卡是谁（读卡面右下角的名条）
3. 按干员归位：同一个干员的 N 张卡放进同一帧
4. 合成 2560×1600 的成片帧，每帧 = 一个干员 + N 个人各自的持有情况

输出是一叠按 `001-能天使.png … 141-塔露拉.png` 命名的图，直接拖进剪辑软件即可。

**没有这张卡的参与者**，该格用优先级填充：

```
本人梗图（表情包）  >  默认占位卡（assets/placeholder.png）
```

## 四、技术路线

### 1. 卡面切图 —— `ark_card/plate.py`

**不用固定网格，用「页面底色 + 列间隙」反推。** 固定网格是所有切图缺陷的来源（左边空白、名字被切、底部多一条、顶部白边）。

算法顺序：

1. **页面底色**：对整图做颜色量化，取出现次数最多的颜色当背景色；
   与底色通道差 < `BG_TOL=26` 记为「空像素」。
2. **列**：每一列从上到下找最长的连续空段，若 > 0.55×图高，说明这列是列间隙；
   相邻间隙中心的差值的众数 = 列距 `pitch`，间隙之间的宽度 = 卡宽 `cw`。
   再按 `pitch` 向两边补齐，允许贴边列超出画面 `EDGE_SLACK=12` 像素。
3. **侧栏过滤**：整列又暗又均匀的（右侧职业/筛选栏）用 `_panel_mask` 排掉，
   阈值「暗均匀列占比 > 72% 即视为侧栏」。
4. **行**：取中间几列做亮度剖面 `prof`。
   - 卡顶：亮带结束处（`_bands`，亮度 > 232）或页面→卡面的硬边（`_tops`）。
   - 卡底：暗→亮处取暗带里最暗的一行（`_bottoms`），避开名条高光。
   - 卡高 `card_h`：优先用实测的 top/bottom 差；没有时退化为 `1.99×cw`。
   - 行只接受 `card_h ± 6px` 内的，避免把半截行当成整行。
5. **两道教验**（都踩过坑才加的）：
   - 名条带亮度必须 < 125：名条是深色，否则说明切歪了。
   - **相邻两行行距必须 ≥ 0.8×card_h**：窗口工具栏会被误判成一行，
     它和真正第一行的距离往往小于一个卡高，直接丢掉。

输出 `(cards, Grid)`，`Grid` 带 `cols/rows/card_w/card_h`。命名键用 `divmod(k, cols)` 得行列。

### 2. 干员识别 —— `ark_card/ocr.py`

1. **取条**：卡面底部 13% 是名条（`_name_strip`）。**不放大**——实测 3× 与 1× 命中率相同（40/40），1× 快 1.6 倍。
2. **候选清洗**：`clean_name` 只保留中日文/字母/数字/中点，去掉符号与「LV」「MAX」等。
3. **排掉职业代号**：名条上还有 `ISW`、`ART`、`PLX`、`7WW` 之类职业图标文字。
   形状判据 `^[A-Za-z0-9]{2,6}$` 且不在 `order.csv` 里的，直接丢弃。
   （不排会怎样：`ISW` 含 `W`，以子串方式抢走真正的干员 `W`。）
4. **选名 `pick_name`**：对每个候选算与 `order.csv` 全体名字的最高相似度，键 `(相似度, OCR置信度, 长度)`。
   - 短名（1~2 字）会抢长名：若选中 ≤2 字、同时存在 ≥3 字且相似度 ≥0.75 的候选，改选长的。
5. **对齐 `match_order`**：把名字映射到正式名，阈值 **0.70**。
6. **相似度 `_sim`**（这一条非常关键）：

```
完全相等            → 1.0
一方是另一方的子串   → 短长度 / 长长度        ← 不是 0.9！
其余                → difflib 比率
```

子串一律给 0.9 会让**五星名抢走六星的位置**：`拉普兰德⊂荒芜拉普兰德`、
`火龙S黑角⊃黑`、`阿米娅⊃阿`。按长度占比算，这些分别是 0.67 / 0.20 / 0.33，
自然被 0.70 阈值挡住；而真正的错别字（`司霆惊垫`→`司霆惊蛰`=0.87）仍能纠正。

### 3. 合成 —— `ark_card/notebook.py`

- **坐标系**：一切按 `CANVAS=(2138,1316)` 的页面坐标算，最后整体映射到背景图里检测出的纸面矩形（成片 2560×1600）。
- **版式 `layout_for(n)`**：按人数选 6/8/12/20 格。卡片和名片条尺寸由「列宽最大化」反推，所以不同人数尺寸不同，同一人数永远一致。
- **名片条**：比卡片左右各宽 `HDR_PAD_RATIO=0.20`，外沿正好贴到 `EDGE_MARGIN=103`（这就是「左右贴齐纸边」的来源）。
- **日期印**：整组缩放 0.63 贴进 `DATE_TARGET=(1666,1250,2128,1314)`，用固定 `DATE_REF` 保证模板与帧对齐。
- **两段式**：先 `build_notebook_template()` 出底图+塔+日期框，再对每帧只贴名片/卡面/日期数字，避免每帧重算版式。

实测冻结参数（12 人）：

```
卡 232×442   名片条 326×102   最低边 1240
列 x = 106 / 440 / 774 / 1108 / 1441 / 1775
名片条跨度 60…2053，中间五条空档各 102，外侧 46/47
行顶 197 / 798，行底 639 / 1240，卡→日期印 10px
```

### 4. 名片切图 —— `ark_card/profile.py`

按原图比例套预设框，不识别内容：

```
BOX_WIDE = (965/2292, 60/1080, 1888/2292, 348/1080)   # 2292×1080
BOX_169  = (1013/1920, 115/1080, 1788/1920, 357/1080) # 1920×1080
```

输出比例 3.20。已是名片（比例接近）的图 `looks_like_card` 会直接放行不重复裁。

## 五、数据与缓存约定

`data/state.json` 每人一个 dict：

```json
"<参与者>": {
  "<截图文件名>#<行>#<列>@<文件内容 md5 前 8 位>": {"texts": [...], "scores": [...]}
}
```

**键里带内容指纹**，因为素材经常「同名不同图」（`1.png`、`2f7a….jpeg`）。
只按文件名做键会串味：换了新截图但名字一样，旧 OCR 结果被套到新卡上，干员全张冠李戴。

`data/overrides.json` 是人工兜底，优先级最高：

```json
"<参与者>": { "<同上键>": "<正式干员名>" }
```

## 六、怎么跑

### 先装依赖

```bash
pip install -r requirements.txt
```

里面有四个包，分两类：

| 包 | 用途 | 不装会怎样 |
|---|---|---|
| `pillow` `numpy` | 切图 / 合成，必需 | 什么都跑不了 |
| `paddleocr` `paddlepaddle` | **认干员名** | 切图照常，但 `ingest.py` 在识别第一步直接抛 `RuntimeError("paddleocr 不可用")` |

`paddlepaddle` 体积较大（几百 MB，含推理运行时），首次运行还会自动下载 OCR 模型到
`data/paddlex`（约 100 MB）。如果只想切图不认名，可以不装这两个，
但要自己往 `data/overrides.json` 里填名字——否则所有卡都会落在「未识别」里。

> 识别是**逐张卡单独预测**的，不是整批塞给模型。这是刻意的：
> 一次喂几百张会让 paddle 进程直接崩（段错误），单张跑慢一点但稳定。

### 跑

```bash
# 全量（已处理的参与者自动跳过）
python tools/ingest.py

# 只处理指定人
python tools/ingest.py --only 某人 --only 另一人

# 强制重切（会重新算卡片边界；缓存仍在，OCR 只补新增卡）
python tools/ingest.py --recrop 某人

# 全部重来
python tools/ingest.py --force
```

`ingest.py` 只做「切图 + 识别 + 命名」，**不出成片**。
成片要自己写十几行调用 `notebook.compose_notebook`（`tools/final1.py`、`tools/final2.py` 是现成范例）。

改过切图算法后，维护者本地要跑 `test/regress.py`（不在本仓库内）：
它拿多套真实切图集 + 4 档版式跟基线对比，**任何一项 FAIL 都不要往上叠新改动**。

合成本身不在 ingest 里，按需自己写几行（`tools/final1.py`、`tools/final2.py` 是现成范例）：

```python
geom = NB.layout_for(12)
entries = [{'nick': 名, 'header': 名片路径, 'card': 卡路径} or
           {'nick': 名, 'header': ..., 'placeholder': 梗图, 'mode': 'contain'}]
NB.compose_notebook(entries, out, 模板路径, 日期, 字体, 'cover', chrome=False)
```

## 七、踩过的坑（必读）

| 现象 | 根因 | 现在的处理 |
|---|---|---|
| 左边一片空白 / 右下名字被切 / 底部多一条 / 顶部白边 | 早期用固定网格 | 全部改成间隙反推（`plate.py`） |
| 最右一列整列丢失 | 截图在卡边切断，`x+cw` 超出画面几个像素 | `EDGE_SLACK=12` |
| 名条高光被当成卡底，名字被切掉 | 名条有白色描边 | 要求亮度持续偏暗，再取暗带最暗行 |
| 整行被丢 | 有的界面名条底色偏灰（实测 111），阈值 105 卡太死 | 放宽到 125 |
| 工具栏被当成一行，切出 9 张废卡 | 顶部工具栏也满足「亮带+暗底」 | 行距必须 ≥0.8×卡高 |
| 卡片从画面最顶部开始的那张图整行漏切 | 上方没有页面亮带，`_tops` 无触发 | **仍未自动解决**，人工按坐标补切 |
| 五星卡占了六星的位置 | 子串相似度给 0.9 | `_sim` 改按长度占比；`match_order` 阈值 0.70 |
| 繁体字名字被丢（`緘默德克萨斯`） | 繁简字形不同，相似度掉到 0.8 | 人工 override |
| 短名单字被漏（年/令/夕/黑/余） | 名条太小，OCR 一个字都不出 | 逐张看图确认后写 override |
| 换素材后干员名全错位 | 缓存键只有文件名+行列 | 键里加内容 md5 |
| 某个干员那格显示了别的干员 | 同一张卡被存成两个名字（`塔露拉` 被存成 `W`），成片按名字取图就取错 | 入库末尾加**同目录内容查重**，重复会打印警告 |
| 只切到第二行，第一行整行漏 | 同「工具栏」那行的情况相反——上方无亮带 | 同上，人工补 |
| 横幅/海报被当成卡 | `crop_cards` 会抛「没找到列间隙」 | ingest 跳过该文件，不影响同人其他截图 |

## 八、已知边界

- **只认六星**：`order.csv` 只有 141 个六星，五星/四星的卡会被识别出来但按规则丢弃，这是刻意的。
- **行数靠图**：一张图能切几行取决于卡片高度是否可测。卡片从画面最顶开始、
  且顶部是亮色星级条的截图，第一行会漏，需要人工补。
- **单字名必查**：`年/令/夕/黑/余/阿/W` 这类单字名 OCR 失败率明显偏高，
  批量跑完**一定要抽查缺失列表**里有没有它们，有就翻图确认。
- **风格不统一**：参与者截图的分辨率、列数（8 或 9）、窗口装饰都不同，
  算法对这些都是自适应的，但**同一张图里必须只有一种卡片尺寸**。

## 十、素材与分发

| 文件 | 是否随仓库 | 说明 |
|---|---|---|
| `assets/order.csv` | ✅ | 141 个六星的名字与实装日期，纯文本 |
| `assets/placeholder.png` | ✅ | 默认占位卡（灰底 + 十字），自制图 |
| `assets/bg_scene.png` | ❌ | 视频底图，含游戏原画 |
| `assets/bg.png` / `bg_blank.png` | ❌ | 同上 |
| `assets/date_font.ttf` | ❌ | 商业字体，不可再分发 |

也就是说：**clone 下来能跑切图、能识别干员，但没有底图和字体就出不了成片**。

缺的素材不要去找「补丁包」——直接把 `compose_notebook` 的 `background` / `font_path`
参数指向你自己的文件。

## 九、改代码的守则

1. **先跑 `test/regress.py`**，改完再跑一次。切图算法的任何改动都可能让历史数据全错。
2. **不要改缓存键格式**，除非同时清 `data/state.json`——否则所有历史结果作废且会串味。
3. **行/列检测宁严勿松**：多切一张废卡比漏掉一行更容易被发现，但漏行是静默的，所以两道校验（名条亮度、行距）都保留。
4. **版式改动要同时看 6/8/12/20 四档**，四档共用同一套比例推导。
5. **手工补的卡不会被 `--recrop` 保留**（会按截图重建目录），补完记得说明或改存 overrides。
6. **留意入库末尾的重复警告**：`⚠ 发现内容重复的卡` 表示同一张图被命成了两个干员，
   成片里那一格会是错的。看到就查 `overrides` 或直接重切该参与者。
